# 开发区科工作任务看板 · 正式版技术方案

> 本文是正式版的实施设计，不代表当前预览版已经具备局域网多人能力。  
> 当前交付物是用于业务和界面确认的交互预览；正式版在确认后开发。

---

## 一、目标形态

在科长办公电脑上运行一个独立的 Windows EXE。EXE 同时承担：

1. 局域网 Web 服务；
2. 数据库与文件存储；
3. 自动备份任务；
4. 登录与权限校验；
5. 周期任务自动生成。

其他科室成员不安装任何软件，直接在浏览器输入：

```
http://主机局域网IP:5080
```

即可使用。5 人规模的并发量很低，单机集中服务足够稳定。

---

## 二、技术选型

| 部分 | 方案 | 原因 |
|---|---|---|
| 服务端 | .NET 8 / ASP.NET Core Minimal API | Windows 生态成熟，可发布为自包含单文件 EXE |
| 数据库 | SQLite（WAL 模式） | 零安装、单文件、便于备份；5 人并发足够 |
| 前端 | 复用当前预览版静态页面 | 已形成完整视觉与交互，正式版替换数据访问层 |
| 认证 | Cookie 会话 + PBKDF2/BCrypt 密码哈希 | 不引入外部身份服务，局域网内简单可靠 |
| Excel | 保留当前无依赖 XLSX 导出 | 已通过 Excel/WPS 兼容验证 |
| 部署 | `win-x64` 自包含单文件发布 | 目标电脑无需安装 .NET 运行时 |
| 备份 | SQLite Online Backup API + 每日定时任务 | 热备份不锁库，恢复可控 |
| 日志 | 本地滚动日志文件 | 出问题可排查，不暴露给普通用户 |

不引入 Redis、消息队列、复杂前端框架或图表库。这个系统的核心是稳定、易用、可维护。

## 三、角色与权限（服务端强制）

| 能力 | 管理与审核 | 任务办理 |
|---|---|---|
| 查看全部任务、周期历史、归档 | 是 | 是 |
| 任务清单默认范围 | 全部任务 | 仅本人负责 |
| 筛选查看其他成员的任务 | 是 | 是 |
| 新建一次性任务 | 是（可指派任何人） | 是（责任人只能是本人） |
| 新建周期任务 | 是 | 否 |
| 编辑任务元数据、调整责任人 | 是（任意未办结任务） | 是（自己创建且本人负责的待办/办理中任务；不能改责任人） |
| 更新自己负责任务的办理状态 | 是 | 是 |
| 记录自己负责任务的任务进展 | 是 | 是 |
| 记录他人负责任务的任务进展 | 否 | 否 |
| 更新他人负责任务的办理状态 | 否 | 否 |
| 审核通过 / 退回 | 是 | 否 |
| 审核自己提交的任务 | 否（需另一位管理员） | — |
| 工作分类新增、重命名、停用、删除 | 是 | 否 |
| 人员新增、编辑、停用 | 是 | 否 |
| 备份、恢复 | 是 | 否 |
| 导出任务 Excel | 是 | 是 |
| 切换界面配色 | 是 | 是 |

权限必须在 API 层校验，不能依赖前端隐藏按钮。

初始管理员为姚琦、郭军；后续可在系统设置中增加或调整管理权限。系统必须保证至少保留一名在用管理员。

## 四、核心数据模型

### 1. people

| 字段 | 说明 |
|---|---|
| id | 主键 |
| name | 姓名 |
| title | 职务 |
| role | `manager` / `staff` |
| active | 是否在用 |
| password_hash | 密码哈希 |
| created_at / updated_at | 时间 |

人员不物理删除。停用前必须没有未办结任务，或者先批量重新指派。

### 2. work_categories（工作分类）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| name | 分类名称，启用中名称唯一 |
| tone | 展示色序号（0–4） |
| active | 是否启用；停用不删除，删除需先转移关联任务 |
| sort_order | 显示顺序 |
| created_at / updated_at | 时间 |

分类使用固定 `id`，重命名只改名称，不批量修改历史任务；停用后新任务不可选，历史任务仍正常显示。删除分类前必须先把关联任务和周期规则转入另一个启用分类，避免历史记录失去分类；系统至少保留一个启用中的分类。普通成员只能选择分类，不能维护。预览版为简化以分类名称存储，正式版统一改为 `category_id`。

### 3. task_templates（周期规则）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| title / description / category_id | 任务内容 / 工作分类 |
| assignee_id | 默认责任人 |
| cycle | `weekly` / `monthly` / `quarterly` |
| anchor_due / due_time | 首期截止日期和时间，用于计算后续期次 |
| active | 运行 / 暂停 |
| created_by / created_at | 创建信息 |

### 4. tasks（任务实例，一次性任务也存于此）

| 字段 | 说明 |
|---|---|
| id / code | 内部 ID / 任务编号 |
| template_id | 周期任务所属规则；一次性为空 |
| period_key | 期次键，如 `2026-W45`、`2026-11`、`2026-Q4` |
| title / description / category_id | 任务内容 / 工作分类 |
| type | `one_time` / `recurring` |
| assignee_id / creator_id | 责任人 / 创建人 |
| status | `pending` / `in_progress` / `review` / `completed` |
| due_date / due_time | 截止日期和截止时间（默认 18:00） |
| started_at / submitted_at / completed_at | 关键时间 |
| reviewer_id / review_note | 审核信息 |
| version | 乐观锁版本号 |
| created_at / updated_at | 时间 |

约束：

```sql
UNIQUE(template_id, period_key)
```

用于防止重启、重复触发或多请求导致同一期任务重复生成。

### 5. task_progress（任务进展）

| 字段 | 说明 |
|---|---|
| id / task_id | 主键 / 任务 |
| actor_id | 记录人（必须是任务责任人） |
| kind | `update` 过程进展 / `result` 办理结果 |
| content | 文字内容 |
| created_at | 时间 |

任务进展只追加、不修改。办理中可多次记录，提交审核时必须新增一条 `result` 记录。审核人打开任务时直接查看这条时间线，不再单独维护“办理情况”字段。

### 6. task_events（操作记录）

| 字段 | 说明 |
|---|---|
| id / task_id | 主键 / 任务 |
| actor_id | 操作人 |
| action | created / started / progress / submitted / withdrawn / approved / rejected / updated / reassigned |
| note | 意见或说明 |
| created_at | 时间 |

操作记录只追加、不修改，用于追溯系统动作；前端默认折叠展示，不和人写的任务进展混在一起。

### 7. backups（备份记录，可写数据库或文件索引）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| file_name / file_path | 备份文件 |
| reason | auto / manual / pre_restore |
| size | 大小 |
| created_at | 时间 |

## 五、周期任务生成

正式版由服务端后台任务负责，而不是浏览器：

1. 服务启动时执行一次生成检查。
2. 后台任务每天 00:10（Asia/Shanghai）检查所有运行中的周期规则。
3. 根据规则计算当期 `period_key`、`due_date` 和 `due_time`，在事务中尝试插入任务。
4. 依靠 `UNIQUE(template_id, period_key)` 保证幂等。
5. 周期暂停只阻止未来生成，不修改已有任务。
6. 修改规则只影响未来期次；要改当期，单独编辑当期任务。

每期任务生成后是独立记录，拥有独立状态、责任人、任务进展、操作记录和审核结果。

## 六、审核与并发控制

任务状态机：

```
待办 pending
  └─ 责任人开始办理 → 办理中 in_progress
       └─ 责任人提交审核 → 待审核 review
            ├─ 管理员通过 → 已办结 completed
            └─ 管理员退回 → 办理中 in_progress
       └─ 责任人撤回审核 → 办理中
```

服务端规则：

- 只有 `assignee_id = 当前用户` 才能执行开始、记录进展、提交、撤回。
- 提交审核时必须填写办理结果，并写入 `task_progress`（kind = result）。
- 只有 `manager` 才能审核。
- 审核人不能等于任务责任人。
- 所有状态变更在事务中完成，并校验 `version`，避免两个窗口同时操作覆盖。
- 每次状态变更同时写入 `task_events`；记录进展单独写入 `task_progress` 和一条 `progress` 操作记录。
- 已办结任务不可再修改状态或追加进展。
- 普通成员进入任务清单时，服务端默认按其 `assignee_id` 过滤；管理员默认返回全部，仍可主动筛选。
- 普通成员新建任务时，服务端强制 `type = one_time`、`assignee_id = 当前用户`；周期任务只能由管理员创建。
- 普通成员只能编辑 `creator_id` 和 `assignee_id` 都是本人、状态为 `pending` / `in_progress` 的任务，且不能修改责任人。
- 工作分类维护仅管理员可调用；新建任务只能引用启用中的分类，编辑历史任务时允许保留原停用分类。
- 删除工作分类时，服务端必须先校验关联任务和周期规则已全部转移，再删除分类；禁止产生无分类任务。

## 七、提醒规则

首页和提醒接口统一按服务端时间（Asia/Shanghai）计算：

- 截止前 3 天（含第 3 天）：进入“即将到期”。
- 截止前 1 天、截止当天：加强提醒，并显示具体截止时间。
- 超过截止日期时间且未办结：标记逾期；不足 1 天显示小时，超过 1 天显示天数。
- 待审核任务：无论是否临近截止，都进入“待审核提醒”。
- 已办结：不再进入任何到期提醒。

不引入浏览器通知或短信，避免额外依赖；首页、顶部提醒和处理队列已经足够。

## 八、登录与会话

- 首次启动时创建初始管理员账号，并强制修改初始密码。
- 密码使用 BCrypt 或 PBKDF2-SHA256 加盐哈希，绝不存明文。
- 使用 HttpOnly + SameSite=Lax 的会话 Cookie。
- 所有写操作校验登录态、权限和请求来源。
- 连续失败登录限速。
- 局域网内使用 HTTP；如需更严格安全，可在后续增加内网 HTTPS 证书方案。
- 会话空闲超时（例如 8 小时）后重新登录。

预览版右上角的“切换身份”在正式版中会被移除，改为真正的账号登录和退出。

## 九、备份与恢复

### 自动备份

- 每日固定时间自动备份 SQLite 数据库。
- 保留最近 30 份，按日期命名。
- 备份目录与数据目录分离（例如 `D:\科务看板数据\backups`）。
- 启动时检查最近一次备份；超过 24 小时未备份则补一次。
- 备份失败写入日志，并在管理员首页显示警示。

### 手动备份

- “立即备份”在主机创建一份快照。
- “导出备份文件”下载包含数据库与元数据的压缩包或 JSON。
- 恢复前自动创建 `pre_restore` 安全快照。
- 恢复需要管理员二次确认；恢复完成后服务自动校验数据库完整性。

### 恢复演练

交付前至少完成一次真实的“备份 → 修改数据 → 恢复 → 校验”演练，并记录步骤。

## 十、部署方式

### 交付物

- `KewuBoard.exe`（自包含单文件）
- `appsettings.json`（端口、数据目录、备份目录）
- `启动科务看板.cmd`（可选）
- 部署说明和备份恢复说明

### 首次部署

1. 将 EXE 和数据目录放到科长办公电脑的固定路径。
2. 双击 EXE，首次引导设置管理员密码和数据目录。
3. 程序监听 `0.0.0.0:5080`，窗口显示本机局域网访问地址。
4. 在 Windows 防火墙中允许该端口入站。
5. 在路由器上为这台电脑保留固定 IP。
6. 其他电脑用浏览器访问并登录。
7. 建议配置开机自启（任务计划程序或启动文件夹）。

### 日常维护

- 不需要单独安装数据库。
- 升级时替换 EXE，保留数据目录。
- 备份目录定期复制到移动硬盘或另一台电脑。
- 提供“服务状态、数据库大小、最近备份时间、访问地址”运维信息。

## 十一、界面延续

正式版沿用当前预览版的设计语言：

- 深色侧边栏 + 浅色工作区；提供松石绿、黛蓝、暖砂、墨灰四套克制的办公配色，可按浏览器切换；
- 工作台指标分两层：任务总数、待办、办理中、待审核在上，即将到期、已逾期在下；临期提醒紧接指标区；
- 任务清单优先，普通人员默认只看自己，管理员默认看全部，均可筛选；普通成员可新建仅由本人负责的一次性任务；不做复杂图表和积分排名；
- 系统设置提供工作分类维护，支持新增、重命名、停用和删除；删除在用分类前先转移任务，历史任务不丢分类；
- 右侧任务详情抽屉，办理与审核操作集中；任务进展是独立的时间线，提交审核时的办理结果并入同一时间线；
- 周期任务以规则卡片 + 各期记录呈现；
- 桌面与移动端浏览器都能使用。

正式版新增：

- 登录页、修改密码、退出登录；
- 管理员首页的“系统运行状态”提示；
- 数据版本 / 操作日志查询；
- 更完整的错误提示和断网重试。

## 十二、验收标准

1. 主机断网时局域网内仍可访问（不依赖互联网）。
2. 5 人同时在线操作，任务状态不丢失、不互相覆盖。
3. 普通成员无法修改他人办理状态；绕过前端直接调接口也会被拒绝。普通成员新建任务时无法指派他人，也无法创建周期任务。
4. 审核不通过必须填写意见，任务正确退回；提交审核必须填写办理结果，并进入任务进展时间线。
5. 普通人员任务清单默认仅本人，可筛选查看全员；管理员默认全部；任务清单状态数字随筛选范围同步。
6. 普通成员不能新增、重命名、停用或删除工作分类；分类停用后历史任务仍保留，删除在用分类必须先转移任务，新任务只显示启用分类。
7. 四套配色均可正常切换并在刷新后保留，桌面与手机布局无溢出。
8. 周期任务跨周 / 跨月 / 跨季度只生成一次，不重复。
9. 截止前 3 天、前 1 天、逾期、待审核均按规则显示，办结后消失。
10. 导出的 XLSX 在 Excel 和 WPS 中均可正常打开，中文不乱码。
11. 自动备份和手动备份均可恢复，恢复前有安全快照。
12. 主机重启后数据完整，服务可自动恢复运行。
13. 界面在 1366×768 办公电脑和手机浏览器上均可正常使用。

## 十三、实施顺序

1. **确认预览**：确认界面、周期截止规则、权限边界。
2. **正式版服务端**：数据库、认证、任务 API、审核、周期生成。
3. **前端接入**：替换预览数据层，保留现有界面与交互。
4. **备份与部署**：EXE 打包、主机部署、防火墙和固定 IP。
5. **联调验收**：多人并发、权限越权、周期跨期、备份恢复演练。
6. **交付培训**：管理员操作说明和一页式使用指南。

预览版确认后，再进入正式版开发，不把预览版直接投入正式使用。
